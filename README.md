# Meridian Investment Workbench

React + TypeScript dashboards backed by a Python/FastAPI investment pipeline. The application runs locally with persistent SQLite state. The Equities page uses Alpaca prices and SEC annual reports; the FX page uses Yahoo Finance via yfinance with Twelve Data fallback. The Bonds page uses official FRED Treasury daily yields. Rates, Commodities and the simulated portfolio use an explicit synthetic provider. The demo workspace works without API keys.

## Economic release calendar

The **Economic calendar** button above **News** opens the official **Tradays / MetaQuotes widget** on every route. It presets **High impact only** and displays **yesterday through tomorrow together**, including Actual, Forecast and Previous values. The date range rolls at midnight **Asia/Singapore**. The calendar stays above News when both windows are open; the popup stack scrolls on smaller screens.

The iframe loads directly from `https://www.tradays.com/en/economic-calendar/widget` with provider-supported `importance=8`, `date_mode=0`, and `from`/`to` settings. These settings were verified against the live provider response. The widget's own JavaScript requests actual results around scheduled releases, automatically updating the displayed values. It remains untouched, including its attribution. [MetaQuotes describes the widget's real-time updates here](https://www.tradays.com/en/about). No account, API key or saved calendar snapshot is used. Economic values remain inside the provider iframe.

Click **Yesterday**, **Today** or **Tomorrow** to jump to that day's first high-impact release inside the same scrollable three-day list. This changes the iframe's existing `#prevValue<event-id>` anchor, preserving the three-day date range and live vendor code. A small read-only backend lookup (`GET /api/calendar/tradays/focus`) resolves the first event ID for each Singapore date from the public widget. Successful indexes are shared for five minutes; failed lookups retry after thirty seconds and are never reported as an empty day. The index resets at Singapore midnight, and test app instances disable network access. A day with no releases gets a clear message. Repeating a date click navigates again after manual scrolling. Browser screenshot checks verified the real widget's event anchors.

The outer app reloads the widget after reconnecting, when returning after at least five minutes hidden, every fifteen minutes while visible to reconcile schedule changes, and at Singapore midnight to advance the three-day window. The manual Reload button also opens a fresh widget. The vendor handles result updates between those reloads. Closing the calendar removes the iframe; reopening it gets current data.

**Timezone:** the header uses Singapore calendar dates. The embedded widget defaults to the browser timezone and offers its own timezone selector; choose **GMT +8** for Singapore if necessary. Its own controls can change the initial date or impact filter. Use Reload to restore the requested three-day/high-impact view.

**Connection reporting:** the outer label reports loading, offline, slow loading or that the frame opened. A frame load is not proof that economic data is current: cross-origin browser rules prevent the parent from inspecting the widget's data connection or an HTTP error page inside it. The live feed is controlled by Tradays; provider/network/browser restrictions can interrupt it. The lower helper/status block is omitted so the widget uses the available height. Its native attribution remains inside the unmodified iframe. Loading/offline notices and direct-access links remain in the header or error state.

Checks: `node scripts/test-tradays-calendar.cjs` covers date boundaries, anchor navigation, midnight rollover, reconnection, schedule reconciliation and cleanup; `python -m pytest backend/test_tradays_focus.py` checks date-to-anchor mapping, invalid responses and the shared cache. `node scripts/render-news-smoke.cjs` covers the shared shell and iframe settings. `python scripts/check-tradays.py` makes fresh source requests, validates the high-impact filter and three-day range, and checks the vendor's release-updater assets. `npx playwright test tests/economic-calendar.spec.ts` exercises the wrapper using a synthetic iframe; this workstation's Edge policy blocks remote-debugging browser tests, so source and render checks are reported separately.

## FX forward carry and implied-volatility charts

Two scatter charts sit directly above FX Balance of payments: **USD/ccy carry vs risk correlation** and **Annualized carry vs implied volatility**. By default the carry chart now loads **observed 1Y forward points and spot bid/ask prices from Investing.com's public UK forward tables**, covering EUR, GBP, JPY, CHF, CAD, AUD, NZD, SEK and NOK against USD. No API key is required. Set `FX_INVESTING_FORWARDS_ENABLED=false` in backend `.env` to disable this connection. An explicitly configured normalized forward/options bridge takes precedence over the public source.

The public-source adapter reads the exact **1Y FWD** row, converts midpoint points to outright (`spot midpoint + points midpoint * pip size`, with 0.01 per JPY pip and 0.0001 otherwise), and computes one-year carry. It treats the quoted 1Y tenor as one year: **no exact settlement dates or calendar adjustment are invented**, because those dates are not published. The table and tooltips expose both spot observation dates/times and forward quote times. The two prices can have different timestamps; the carry is indicative midpoint carry, not an executable bid/ask return. The public website has no guaranteed real-time delivery or stable API, and can return HTTP 403 or change its markup. Automatic checking is not streaming.

**The volatility chart uses Saxo's public OTC ATM options report only; no account or API key is needed.** The report currently covers EURUSD, USDJPY, GBPUSD, AUDUSD, USDCAD and USDCHF. NZDUSD, USDSEK and USDNOK remain unavailable when absent from the report. No historical-volatility or policy-rate proxy is substituted. DXY is omitted because it has no single spot/forward funding pair.

The adapter selects the exact `1y` ATM column (or the configured supported tenor) from [Saxo's public report](https://fxowebtools.saxobank.com/otc.html). It uses the volatility level, not its change, the historical-volatility chart or the risk-reversal table. **Values are published report snapshots.** The server checks for new reports every minute while the app is running, including when the browser tab is hidden. The visible chart refreshes every minute after the previous request completes, and catches up on focus/reconnection. A new report replaces the chart values automatically without a page reload or button click. Report publication and successful-check times are displayed separately; fetching an unchanged report never makes its observation time newer.

Failed, malformed or regressed reports preserve the last verified report and its publication time in ignored `data/saxo-fx-volatility.json`. Saved reports are revalidated on restart. Carry and IV can have different observation times and sources. Report observations more than seven days old are flagged; unavailable currencies remain explicitly missing. The report-check worker stops with the server. Set `FX_SAXO_REPORT_ENABLED=false` in backend `.env` to disable this source.

Run `python scripts/check-fx-volatility.py` for a read-only source/coverage check. Tests verify that a newly published report updates the right chart on the next automatic poll, hidden tabs catch up, outages preserve original dates, and source recovery updates the chart. The public forward source retains its existing one-minute checks and delivery limitations.

`GET /api/fx/carry-risk?weeks=52` supplies the charts; `weeks` supports 26, 52 and 104, `refresh=true` checks the sources now, and `saved_only=true` reads saved inputs without network calls. Responses use `Cache-Control: no-store`. The visible page checks the forward sources automatically one minute after the previous request completes, catches up on focus/reconnection, and supports **Refresh charts** and **Refresh FX**. Starting the timer after completion prevents network latency from making the next poll arrive before the backend refresh window. Each successful response replaces the left scatter chart data, so new forward quotes move the points without a page reload or button click. The client update behavior (including changed values, request latency, reconnects and recovery after interruptions) can be verified with `node scripts/test-fx-carry-refresh.cjs`. FRED FX/S&P 500 history is checked every five minutes. H.10 daily observations are published weekly, so the correlation is a historical statistic.

Each public pair refreshes independently: a failed check or regressed quote preserves that pair's previous verified values and timestamps while other pairs update. Public inputs and successful per-pair check times are cached in ignored `data/investing-fx-forwards.json`; snapshots are validated and carry is recalculated on reload. Source quote times are never replaced by fetch times. Quotes older than five minutes and date-only spot observations (including weekend closes) are flagged. Date-only prices retain their date without an invented clock time. Invalid rows, tenors, numbers, crossed markets, future timestamps and timezone changes are rejected. Forward HTTP requests verify TLS, disallow redirects and have bounded size, timeout and concurrency. No credentials enter the browser or snapshots.

Forward carry uses **(spot / forward − 1) × 365 / actual value-date days × 100** for long the pair's base currency. The first chart instead uses long USD; for inverse pair direction it uses **(forward / spot − 1)**, not a sign flip. The second chart keeps standard market pair direction. Weekly risk correlation uses completed calendar weeks, the last common FX/equity observation day in each week, log returns and at least 20 observations; it does not bridge missing weeks. Hover details and the expandable table identify quote times, forward value dates and historical correlation coverage.

An existing normalized combined forward/options bridge can override these adapters: configure backend `.env` with `FX_CARRY_FEED_URL`, optional bearer `FX_CARRY_FEED_TOKEN`, and `FX_CARRY_IV_TENOR` (`1W`, `1M`, `3M`, `6M`, `12M`). HTTPS is required except for a local HTTP desktop bridge; credential-bearing redirects are disabled. Its JSON contract is below (illustrative values only; this example is never loaded as market data):

```json
{
  "provider": "Your entitled provider",
  "as_of": "2026-10-30T12:00:00Z",
  "forward_format": "outright",
  "volatility_unit": "percent",
  "quotes": [{
    "pair": "EUR/USD",
    "spot": 1.10,
    "forward_12m": 1.12,
    "spot_date": "2026-11-03",
    "forward_date": "2027-11-03",
    "quote_time": "2026-10-30T12:00:00Z",
    "implied_volatility_pct": 8.5,
    "iv_tenor": "12M",
    "iv_delta": "ATM",
    "iv_time": "2026-10-30T12:00:00Z"
  }]
}
```

The backend verifies pair identity, explicit units, forward value dates, option tenor/moneyness, finite values and nonfuture/nonregressing source timestamps. Missing pairs remain unavailable; truncated previously covered feeds are rejected. Saved snapshots require the exact-metrics data basis. Checks: `python -m pytest backend/test_fx_carry_risk.py backend/test_fx_sources.py backend/test_fx_config.py` and `npm run build`.

## U.S. Rates macro dashboard

The Rates tab has eleven U.S. panels backed by `GET /api/rates/us`. Four charts at the top compare the daily effective federal funds rate (DFF) with 2Y, 5Y, 10Y and 30Y Treasury yields on a shared percent axis. They use the same history filters and automatic refresh as the macro charts below: CPI goods/services, headline/core PCE inflation, unemployment/nonfarm payroll changes, Atlanta Fed wage growth/average hourly earnings growth, 5-year inflation measures, JOLTS openings/Indeed postings, and total housing under construction. The page checks every minute while visible, catches up after focus/reconnection, and supports the global **Refresh market data** button. New source observations and revisions replace chart values automatically. Sources follow their own release schedules; this is published macro data, not streaming market quotes.

FRED series: `DFF`, `DGS2`, `DGS5`, `DGS10`, `DGS30`, `CUSR0000SAC`, `CUSR0000SAS`, `PCEPI`, `PCEPILFE`, `UNRATE`, `PAYEMS`, `FRBATLWGT3MMAUMHWGO`, `CES0500000003`, `T5YIE`, `EXPINF5YR`, `JTSJOL`, `IHLIDXUS`, `UNDCONTSA`. The backend uses the existing `FRED_API_KEY` (or `BONDS_FRED_API_KEY`), with public FRED CSVs when no key is configured. Keys stay server-side. `RATES_ENABLED=false` disables downloads. Optional trusted TLS certificates use the existing `FX_ANALYTICS_CA_FILE` setting.

CPI/PCE/average hourly earnings are shown as `100 × (level / same-month-prior-year level − 1)`. Nonfarm payroll changes subtract the exact prior calendar month; a missing month is never bridged. The wage tracker is the Atlanta Fed's three-month moving average of median individual 12-month wage growth, not the BLS average-earnings series. JOLTS openings are divided by 1,000 to millions; Indeed remains its published index with its own daily dates. Credit: **Indeed Hiring Lab via FRED**. Housing is the seasonally adjusted stock of new privately owned units under construction in thousands, not starts/completions. Monthly dates indicate reference months, not release dates. History starts in 1990 or the series' later start date.

Each chart labels its axes, units, source and observation dates. Mixed daily/monthly lines retain independent native dates, and missing monthly values remain missing. Series refresh independently; a failed source keeps its dated cache in ignored `data/us-rates.json` while other sources continue updating. Saved inputs are validated and transformations are recomputed on startup. Complete history is refreshed to incorporate revisions; regressed/truncated histories are rejected.

**Zero-coupon inflation swap:** the inflation panel now includes a free DTCC-derived **daily median of executed 5Y USD CPI-U zero-coupon swaps** (`USD_ZCIS_5Y`), alongside genuine FRED `T5YIE` breakevens and Cleveland Fed `EXPINF5YR` expectations. DTCC's public CFTC rates cumulative files provide history; its intraday slices add trades/corrections during the day. The backend resolves the official public bucket from `https://pddata.dtcc.com/ppd/api/general/bucketname`, reads its dashboard's `Cumulative.json` and `Slice.json` indexes, and downloads only validated rates ZIP names from the fixed official DTCC host. No API key, subscription or proxy instrument is required. References: [DTCC public dissemination](https://pddata.dtcc.com/ppd/) and [DTCC market data](https://www.dtcc.com/market-index-data).

The screen requires the exact `USA-CPI-U` underlier, USD legs, a five-year maturity (within seven days for date rolls), a near-spot effective date (−3 to +10 calendar days from execution), and a single payment at maturity on both legs. It excludes annual-coupon structures, packages, nonzero upfront payments and non-trade events. Rates are converted from decimal fixed rates to percent. Eligible trades are equally weighted in the daily median; the chart does **not** claim a streaming dealer bid/ask or benchmark fixing. `CORR`/`EROR` chains revise/remove earlier prints before medians are recomputed, dissemination IDs are deduplicated, and `MODI`/`TERM` are never used as fresh prices. No new rate is fabricated on a day without eligible trades.

DTCC checks run every 60 seconds **in a background worker while the server runs**, including with hidden tabs. The visible page polls every minute and catches up on focus/reconnection. Publication, reporting/block delays and trade availability limit freshness; checking the source never changes an observation's execution timestamp. The panel shows the last eligible trade time, the latest median's trade count, source check time, processed file timestamp and available history start. Older history loads automatically in batches from the rolling daily archive, up to 365 calendar days; intraday backlog is explicitly labelled provisional. A failed file is retried and incomplete files are rejected. Errors keep dated values and show a source warning. Compact lifecycle inputs remain only in ignored local `data/dtcc-inflation.json`; the API/export exposes aggregate observations and counts, never trade-level records. `RATES_DTCC_ENABLED=false` disables this source. `RATES_ENABLED=false` disables all Rates downloads/workers.

An optional `RATES_INFLATION_SWAP_URL` HTTPS JSON bridge overrides DTCC, with optional backend bearer `RATES_INFLATION_SWAP_TOKEN`. The contract requires `provider`, UTC `as_of`, `country: "USA"`, `instrument: "zero_coupon_inflation_swap"`, `index: "CPI-U"`, `tenor_years: 5`, `unit: "percent"`, and `observations: [{date: "YYYY-MM-DD", value: <percent>}, ...]`. No bridge is queried by default. HTTP is accepted only for a local desktop bridge; redirects are disabled.

Read-only verification: `python scripts/check-us-rates.py` or `python scripts/check-dtcc-inflation.py` (run standalone with the server stopped to avoid writing the same cache concurrently; `--batches 8` can prefill more history). Tests: `python -m pytest backend/test_us_rates.py backend/test_dtcc_inflation.py` and `node scripts/test-us-rates.cjs`.

## Official Treasury yields, spreads and butterflies

The Bonds page now has the same evenly spaced, horizontally scrollable country selector as FX BOP. Connected markets are **United States, China, Japan, United Kingdom, Canada and Singapore**. Selecting a country switches its yield cards, history, curve, spreads, butterflies, source/date labels and export together. Prior requests are cancelled and responses must match the selected country. The two analytics groups stay collapsed until expanded; the sources/conventions footer remains removed.

History charts omit dates with no published yields at any maturity, so empty holiday rows do not break yield, spread or butterfly lines. Missing maturities on dates with other published yields still break the affected series; auction-based histories keep their published-date display. No yields or calculated values are filled, and the API/export retains its original dates and missing values.

The US retains its authenticated FRED connection. China uses CCDC's public ChinaBond JSON chart API with all five exact YTM tenors (history from 2006); Japan combines Ministry of Finance daily JGB yields with official 3M Treasury Discount Bill auction yields; the UK combines Bank of England nominal gilt spot curves with the UK DMO's native Treasury-bill XML API; Canada uses one Bank of Canada Valet JSON API request for daily benchmark bond and 3M Treasury-bill yields; Singapore uses the app's JSON adapter over official MAS daily SGS benchmark history. Country snapshots live separately under ignored `data/bond-countries/`. Historical source files are checked daily. All international bond tabs check for new releases every minute while visible, with the existing faster US release-window checks. These are updates to official published observations, not streaming intraday prices.

China has published 3M, 2Y, 5Y, 10Y and 30Y API history for every chart. Singapore has no current 3M point in its selected source; that card and its calculations remain unavailable. UK 3M uses official DMO tender yields; longer maturities use the BoE nominal gilt curve. UK yields are fitted, continuously compounded nominal government spot rates. Canada's 30Y slot is its designated long-term benchmark (remaining maturity varies); its 3M secondary-market yield and all four bond benchmarks are daily. 3m10s and the full Canadian curve use matching observation dates only. Country-specific conventions and publication dates appear next to the relevant data. No other country is shown using US values. China uses the official `yc/queryYz` POST API for daily YTM history and exact source tenor identifiers, converting midnight China timestamps using UTC+8. Its full history is rechecked daily; its latest 90 calendar days are checked each minute and replace that interval only after validation. Duplicate dates, wrong curves/spot-rate substitutions, non-finite values and truncated recent coverage are rejected. A saved-only endpoint response populates each international country immediately while source checks run; outages preserve the original observation and check dates. Backend checks: `python -m pytest backend/test_treasury_yields.py backend/test_sovereign_yields.py backend/test_china_bond_api.py backend/test_japan_bond_data.py backend/test_uk_bond_data.py backend/test_canada_bond_api.py backend/test_singapore_bond_data.py`; fresh China cross-check: `python scripts/check-china-bonds.py`; fresh Japan cross-check: `python scripts/check-japan-bonds.py`; UK source and formula audit: `python scripts/check-uk-bonds.py`; Canada CSV cross-check: `python scripts/check-canada-bonds.py`; Singapore daily-table cross-check: `python scripts/check-singapore-bonds.py`; fresh six-country audit: `python scripts/check-sovereign-bonds.py`.

**Japan:** `GET /api/bonds/treasury?country=JPN` is the app's JSON API adapter over the MOF's public CSV, XLS and HTML releases. The upstream MOF feeds are not a native JSON API and require no key. Daily 2Y/5Y/10Y/30Y yields come from the full JGB archive plus current-month CSV. The 3M card is explicitly an **auction average-price yield**, published roughly weekly, with history from 2009. Its archive is read using `xlrd`; both the current and previous month auction calendars are checked each minute so new results are discovered across month boundaries. The latest published result is rechecked each minute, older results and full archives daily. Original auction dates are retained: 3m10s and the five-point curve only use dates shared by the bills and JGBs. The 3M and 3m10s charts plot published auction observations without filling intervening daily rows. Interbank, call and policy rates are never substituted. Column/unit changes, wrong issue/maturity/date, duplicate auctions and regressed tenor histories are rejected. Japan's displayed source-check time and observation dates distinguish a fresh check from a new release. Intraday Japan quotes would require a separate licensed market-data feed.

**United Kingdom:** `GET /api/bonds/treasury?country=GBR` returns UK-only yields and all seven spread/butterfly plots. The 3M series is the UK Debt Management Office's average accepted Treasury-bill tender yield from its public, keyless XML API (`https://www.dmo.gov.uk/data/XmlDataReport?reportCode=D2.2D`), normally weekly. The four longer maturities remain exact published 2Y/5Y/10Y/30Y points from the BoE nominal government spot curve, continuously compounded; BoE targets publication by noon on the following business day. BoE explicitly does not offer that curve through an upstream API: the app adapts its official workbook releases into JSON. The curve and 3m10s use matching tender/spot observation dates; weekly bill observations are never filled across daily rows. The maturity/basis distinction is shown on the page. Neither bank rate, SONIA nor US yields are substituted.

The UK page checks the current DMO API and BoE release every minute while visible, reads saved observations first, and rechecks large BoE history archives daily. DMO may return an anti-bot block page even with HTTP 200. Invalid XML, wrong schemas/maturities/dates, duplicate tenders, missing/non-finite yields and truncated bill history are rejected. Its last verified bill snapshot retains the original check time in ignored `data/bond-countries/sources/uk-bill-api.json`. If that API fails, the bill observations stay dated with a visible warning and source status; independently downloaded gilt data continues updating. Without any verified bill snapshot, the four gilt series still work and 3M/3m10s remain unavailable. Responses and saved country snapshots include separate `source_checks.gilts` and `source_checks.bills`; partial updates report `status=stale`. Intraday streaming is not provided. Run `python scripts/check-uk-bonds.py --require-all-sources` to require successful fresh verification of both publishers rather than accepting a clearly flagged partial update.

**Canada:** `GET /api/bonds/treasury?country=CAN` uses the Bank of Canada's public, keyless Valet JSON API for all five maturities. The daily 3M bill series is `TB.CDN.90D.MID` (the current identifier corresponding to historical V39065), replacing the former weekly V80691344 connection. Bond series are `BD.CDN.2YR.DQ.YLD`, `BD.CDN.5YR.DQ.YLD`, `BD.CDN.10YR.DQ.YLD` and `BD.CDN.LONG.DQ.YLD`. These are Canadian dollar Government of Canada yields. The long-term benchmark appears in the 30Y position with its varying remaining maturity disclosed; it is not an exact constant-maturity 30-year series. Bill yields are sampled secondary-market averages and bond yields are selected mid-market closing benchmarks. Native daily dates and publication gaps are retained for every chart and calculation, without substitution of US, policy, repo or auction rates.

The five series share a single Valet observations request. Full history is cached in ignored `data/bond-countries/sources/canada-daily-api.json` and rechecked daily; the latest 90 calendar days are checked each minute while the page is visible. Metadata must identify the exact maturities, daily frequency and percent units. Duplicate/future/out-of-range dates, non-finite values, missing required metadata, wrong series and truncated recent tenor coverage are rejected. New releases and revisions update all cards and charts together. Saved-only API responses show the original dated observations while checks run; outages retain the last verified country snapshot and display an error with automatic retry. The source name changes with this upgrade so old weekly-bill snapshots cannot be mistaken for the new daily series. Verify every historical calculation and independently compare current values against separate official bond and money-market CSV group downloads with `python scripts/check-canada-bonds.py`. These are auto-updating official daily releases, not streaming intraday quotes.

MAS's current public APIMG catalogue does not expose an SGS benchmark-yield endpoint; the upstream source is an official statistical Web Forms feed, not a native JSON API. The other four spread plots and both yield butterflies update from current SGS data; the curve has four available benchmark maturities. Historical 30Y publication gaps remain gaps.

Singapore checks its current daily benchmark feed every minute while visible and loads dated saved observations first. Full source history from 2000 where available is validated and cached daily in ignored `data/bond-countries/sources/singapore-sgs-history.json`; subsequent checks replace the latest 90 days (rounded back to the start month accepted by MAS's form). Tokens, yield columns, dates, finite values and complete recent tenor coverage are validated before replacing saved data. A source failure preserves the last verified country snapshot, its original check/observation dates and a visible retry message. The country source label changes on this upgrade so the previous five-minute connector's snapshot cannot be mistaken for a fresh check. No external API key is required. These are automatically retrieved official closing releases, not intraday quotes. `python scripts/check-singapore-bonds.py` independently compares all four current yields with MAS's separate Daily SGS Prices closing table and recomputes every available historical spread and butterfly.

Spreads are **(longer yield - shorter yield) x 100** in basis points. Butterflies are **(2 x belly yield - front yield - back yield) x 100**: 2 x 5Y - 2Y - 10Y, and 2 x 10Y - 2Y - 30Y. A positive butterfly means the belly yield exceeds the mean of its wings. These are unweighted yield combinations, not DV01-neutral trade returns. Every calculation requires all of its legs on the same observation date. Values are never forward-filled, synthesized or derived from mixed dates. Card changes compare consecutive available observations; curve and chart labels display their actual dates.

**Update cadence:** FRED H.15 series are published **daily**, not intraday ticks. The Federal Reserve schedules H.15 at 16:15 Eastern on business days; FRED publication can follow later. Browser and backend check every minute on weekdays from 20:00–23:00 UTC (covering the release in both DST seasons and subsequent publication), and every five minutes otherwise. While visible, the browser reevaluates this schedule every second; new observations and revisions replace every yield card, curve and spread/butterfly chart automatically. It catches up after device sleep or an overdue return to the tab, remembers reconnects while hidden, and retries failures thirty seconds after completion. Explicit Refresh yields / the global Bonds refresh checks immediately. Backend requests share the same source cadence; concurrent requests share the completed result, and failures back off for thirty seconds. The page distinguishes latest observation date from source-check time and warns when publication age exceeds seven calendar days. A successful HTTP response never relabels old observations as new market ticks. Keep the app running and the Bonds page visible for continuous checks; opening it again checks the source.

With backend `BONDS_FRED_API_KEY` configured, the primary connection is FRED's official `fred/series/observations` JSON API. ## SEC 10-K connection

Selecting a company in the equities screener automatically requests `POST /api/equities/sec/{symbol}/sync`. The backend resolves an exact SEC ticker/CIK mapping, retrieves the submissions history and company-facts JSON, selects the latest original Form 10-K by fiscal period, downloads the full filing, and imports matching standard US-GAAP annual facts. The workbench shows the fiscal period, filing date, CIK, accession, original SEC link, full report download, warnings, and per-field tag/formula/source provenance. A manual reload refreshes the report; normal selections use a one-hour report cache and the ticker mapping is cached for a day.

The APIs are public and do not require an SEC API key. Requests identify this application, are serialized at no more than four per second, and never send Alpaca credentials. Set backend `SEC_USER_AGENT` to your application name and real administrator contact for your deployment, following SEC fair-access guidance; the default identifies Meridian's single-user research client without inventing a contact address. Set `SEC_ENABLED=false` to disable external SEC access. Isolated test instances disable real requests by default.

Annual facts are matched on accession, end date, USD/share units and 330-380-day duration; fiscal-year labels alone are insufficient because comparative figures share the latest filing's FY label. Latest-report comparatives take precedence; older original 10-Ks can provide opening balances. Ambiguous values and missing tags remain blank. Gross profit can be derived from reported revenue minus cost of revenue. Total debt is derived only when the current and noncurrent debt components, or total long-term debt plus explicit short-term borrowings, are both available. Invested capital uses book equity plus debt minus cash only when every component is available and the result is positive. Absent short-term debt and issuance tags are never assumed zero. Zero cash issuance cannot establish absence of non-cash issuance, so the no-issuance F-Score test often requires manual review.

The API does not supply custom dimensional tags through company facts. Foreign issuers that file 20-F/40-F and funds without a company 10-K are explicitly marked unavailable for this importer. A 10-K amendment is linked and flagged for review; this importer uses the original annual report. Annual shares remain historical and require review for subsequent splits and share-class differences. WACC, forecast ROIC, growth and competitive-advantage duration remain user assumptions.

Imported SEC data is stored under a separate `equity_sec` key. Existing manual worksheets and unsaved browser edits are preserved; edited worksheet values apply after Save & calculate. Repeated cached sync requests are idempotent. No portfolio cash, holdings, rebalancing or Alpaca orders are changed. SEC failures appear in the panel, preserve saved inputs and offer a retry. A filing download failure is distinguished from available financial facts.

Full filings are cached in `data/sec-cache/`, excluded from the release archive, and served as attachments from `GET /api/equities/sec/{symbol}/document` with a sandbox CSP. Filing HTML is not injected into the React page or interpreted as instructions. SEC responses, including embedded filing text, are external data.

## Rebalancing on Portfolio & Risk

The rebalancing workspace sits below **Your book**. Set per-instrument target weights with sliders or number inputs; cash is the residual. Use the transition-strength slider to compare a partial move with the full target. Optional instruments can be added from the paper-eligible universe. The backend rounds native lots, simulates sells before buys, deducts adverse slippage and fees, and recomputes the same four risk metrics using the projected post-cost holdings. The comparison includes before/after percentages, dollar VaR/ES, turnover, costs, cash, a historical index chart and an exportable trade basket. Invalid or unfunded scenarios cannot execute.

Save the draft targets as a strategic policy to anchor drift monitoring. The recommendation checks each validated snapshot against those saved targets, holds inside tolerance bands, and makes partial corrections toward their nearest boundaries outside the bands. A turnover budget scales the normal recommendation; immaterial weight changes are suppressed. Hard risk breaches take priority. Defaults of ±2 percentage points, 50% correction and 10% gross traded notional/NAV per review are illustrative settings to calibrate in walk-forward tests, not paper-prescribed optimal values. Manual scenarios may exceed this soft turnover budget; the interface flags the override. All concentration, gross exposure, cash and tradability limits remain hard gates.

The UI refreshes workspace data every 30 seconds while visible and on explicit refresh, without overwriting draft sliders. It does not ingest new external feeds itself. The future data adapters must publish fresh, validated snapshots with correct quote units, vintages, lot sizes and historical coverage. Reliable prices alone do not supply expected returns, signal persistence, transaction-cost/impact parameters or executable liquidity. Recommendation outputs remain conditional on the saved policy and available models.

**Approve paper rebalance** executes the reviewed basket only. It rejects changed holdings, quotes, policies or limits, rechecks the book and all trades, and commits cash, quantities, costs and hash-linked fill events in one database transaction. Failed baskets roll back completely. Retrying an identical request does not trade twice. No unattended rebalancing is scheduled.

Research translation: Boyd et al. motivate explicit constraints/costs; Donohue–Yip motivate no-trade bands and boundary corrections; Gârleanu–Pedersen motivate partial adjustment; Almgren–Chriss motivate separating allocation from execution urgency. This is an explainable policy heuristic, not a numerical replication of those papers. A multi-period optimizer, predictive aim portfolio and impact-optimal schedule require calibrated forecasts and liquidity inputs. The 2003 publisher text was inaccessible; its role is based on the supplied summary, with the no-trade-region principle also supported by Leland's public research. References and these limits are exposed in the recommendation panel.

API routes: `GET/PUT /api/rebalance/policy`, `POST /api/rebalance/preview`, and `POST /api/rebalance/execute`.

## Scope and limitations

- No LLM provider is connected. Specialist outputs are clearly identified as rule-based; natural-language questions are saved as context, with exact symbol filtering. Open-ended semantic research requires a future LLM adapter.
- Paper execution supports selected USD equities and illustrative Treasury cash bonds only. FX, rate series, indices and commodities are monitoring-only.
- Bond quantities are face amount and valuation is face × price / 100. DV01 is a duration approximation. Coupon/accrual, settlement, corporate actions, funding, borrow, FX conversion, margin and contract roll/delivery are not implemented.
- Backtests are price-return experiments on synthetic weekday bars, with full fills. They omit exchange holidays and the preceding lifecycle cash flows. They are not evidence of strategy performance.
- This is a local single-user application. It binds to loopback, rejects cross-origin writes, and has no production identity integration. Add authentication, authorization, TLS, secret management and operational monitoring before exposing it to other users or connecting sensitive data.
- Hash linking detects altered records during verification; it does not make storage immutable against a privileged operator rewriting the database.

- **[International investment position, 36-10-0485-01](https://www150.statcan.gc.ca/t1/tbl1/en/tv.action?pid=3610048501):** all-country official international reserve assets at market value, quarter-end CAD, including monetary gold where held. ## FX options trade heatmap

It reads the published representative ATM volatility (not a recomputed bid/ask midpoint) for all 13 tenors from 1D through 18M, 2Y and 3Y. The [CFETS pricing-parameter table](https://www.chinamoney.org.cn/english/bmkycvdpp/) supplies OTC mean spot, swap points and actual expiry dates; forward outright = spot + points × 0.0001. Log-linear outright interpolation uses those expiry dates, and total-variance interpolation uses the ATM tenor curve. The existing undiscounted Black forward sensitivities and gross USD conversion apply. No curve is extrapolated past source coverage; USD/CNH prints are excluded.

CFETS publishes volatility at 10:00, 11:00, 14:00, 15:00 and 16:00 China/Singapore time on trading days, and daily spot/forward pricing parameters at 17:00. **Automatic updates follow these publications; they are not tick-by-tick quotes.** The FX options status shows model valuation, actual trade time, CFETS fixing time, CFETS successful-check time, spot/forward reference date, pricing successful-check time and DTCC check time separately. Missing expected weekday publications are flagged after a ten-minute grace (Chinese holidays may differ). Inputs over seven days old disable Greek estimates.
